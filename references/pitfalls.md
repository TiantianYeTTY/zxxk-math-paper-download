# 踩坑记录与修复方案（全部来自 2026-10-12~14 真实任务）

按严重程度排序。每个坑位含：现象 → 根因 → 修复。执行下载前通读一遍，遇到异常时回来对照。

---

## 坑位 1：Chrome 标签页在后台 → 下载点击被静默忽略（最大坑位）

- **现象**：点击下载按钮后无任何反应——无弹窗、无下载、无报错。表现为 `no_file, pageState:[]`（空失败）。曾误判为"资源服务器损坏"，实际 12+ 份正常资源因此"失败"。
- **根因**：学科网下载 JS 检测 `document.visibilityState`，标签页 `hidden` 时直接 return，连弹窗都不渲染。
- **修复**：
  1. 下载前让用户把 Chrome 窗口和目标标签页置前（点一下窗口即可）；
  2. 脚本每份下载前检查 `document.visibilityState === "visible"`，hidden 则轮询等待（batch_download.js 已内置，上限 15 分钟）；
  3. 诊断口诀：**空失败 = 先查 visibilityState**，不要先怀疑资源或账号。
- **教训**：诊断时用 `JSON.stringify({vis: document.visibilityState})` 一击定位；曾浪费 3 轮排查在"限速/资源损坏"的错误假设上。

## 坑位 2：下载限速/风控（两种形态）

- **形态 A（显式）**：弹微信扫码验证——跨域 iframe `downloadnew.zxxk.com/risk-c...`（480×399），文案"为了您的账号安全，请用微信完成扫码验证后继续下载"。扫码微信关联的手机号必须与学科网账号绑定手机一致。
- **形态 B（静默）**：点击下载直接无响应，连验证弹窗都不弹（冷却期）。
- **触发条件**：实测约 20-25 份/天；超过后当日进入冷却（隔夜恢复）。两天累计 ~80 份必触发。
- **修复**：每份间隔 ≥60 秒（脚本 70-80 秒抖动）；单日控制在 25 份内；触发后停止当日操作，次日重试；重试时先单份试水，正常再批量。
- **注意**：同步树 ID 比对（翻页爬列表）不消耗下载配额，不受风控影响。

## 坑位 3：旧教材卷混入（用户最不满的错误）

- **现象**：下载了同凯中学 2023-2024 八年级期中卷，被用户指出"不是沪教版五四制"。
- **根因**：期中卷详情页**没有教材版本字段**，标题不写新旧教材；我最初只验证了"上海地区+无外地版本标签"，未区分新旧教材 edition。且"沪教版（五四制）"这个名称同时覆盖新旧版（都是上海五四学制体系），大范围验证会漏掉 edition 区分。
- **修复**（三层核验，详见 references/textbook-verification.md）：
  1. 学年审核：官方新教材滚动时间线（六七=2024学年起、八=2025学年起、九=2026学年起）；
  2. 内容级验证：docx 内文查新教材独有章节（决定性证据）；
  3. 同步树 ID 比对：教材同步树官方列表与我们资源 ID 求交集。
- **教训**：立项前先和用户确认"验收标准的确切定义"（站内标签名 vs 官方文件术语 vs 新旧 edition），术语错位会导致返工。

## 坑位 4：风控验证墙的弹窗 iframe 是跨域的

- **现象**：确认弹窗早期是 `about:blank`（可读 contentDocument），风控验证弹窗却是 `downloadnew.zxxk.com` 跨域 iframe，`contentDocument` 为 null，脚本读不到内容也无法点按钮。
- **修复**：跨域弹窗无法自动化——出现 risk-c iframe 即停止批量，请用户人工扫码。判断方式：iframe src 含 `downloadnew.zxxk.com` 且尺寸 480×399。

## 坑位 5：后台任务沙箱拒绝文件写入（CODEBUDDY_BROKER_DENY）

- **现象**：批量脚本在后台任务中运行时，`fs.writeFileSync` 偶发被 broker 拒绝，脚本崩溃。且已完成的 done 记录丢失 → 下次运行重复下载。
- **修复**：`saveLog` 包 try/catch（写失败仅告警不中断）；用文件系统实际状态对账日志，不盲信日志（曾因日志写失败导致重复下载+文件意外丢失）。

## 坑位 6：页面 <a> 元素可能没有 href 属性

- **现象**：采集列表资源 ID 的 eval 偶发 `{"error":"Uncaught"}`。
- **根因**：部分 `<a>` 无 href，`getAttribute("href")` 返回 null，`.match()` 抛 TypeError。且 `.filter(Boolean)` 写在 map 之后救不了（异常发生在 map 内部）。
- **修复**：map 内先判空：`const h = a.getAttribute("href"); if (!h) return null; const m = h.match(/soft\/(\d+)/); return m ? m[1] : null;`

## 坑位 7：Shell 单引号让 JS 转义符失效

- **现象**：`curl -d '...querySelectorAll("a[href*=\"/soft/\"]")...'` 报 `{"error":"Uncaught"}`。
- **根因**：单引号字符串里 `\"` 以字面反斜杠+引号传给 JS，`a[href*=\"/soft/\"]` 是非法 CSS 选择器。
- **修复**：属性值含 `/` 时不要用引号包裹（`a[href*=soft]` 合法）；或改用 getAttribute+regex 形式；或用双引号包裹 -d 参数（但此时 JS 里的双引号要转义）。regex 字面量 `/soft\/(\d+)/` 在单引号里是安全的。

## 坑位 8：ZIP 内文件名 GBK 乱码

- **现象**：学科网 ZIP 内的 docx 文件名解压后乱码。
- **修复**：extract_zips.py 对每个条目做 `filename.encode("cp437").decode("gbk")` 还原，失败则用原名。解压成功后删除 zip。

## 坑位 9：资源内容与标题不符（错包）

- **现象**：资源"建平康梧九年级期中卷"（55466448）解压后是六年级知识清单。
- **根因**：当时用户在并行进行另一个六年级下载任务，站点按账号下发内容串包（用户已确认原因）。
- **修复**：解压后抽查文件夹名与资源标题一致性；不一致移入 `_待核验/`，勿混入年级文件夹。用户并行下载期间避免大批量。

## 坑位 10：Chrome 重名文件加时间后缀

- **现象**：文件名出现" 19.14.57"式后缀。
- **根因**：同名文件已存在时 Chrome 自动加时间戳。日志写失败导致重复下载时高发。
- **修复**：移文件时用 glob 通配匹配前缀；对账以文件系统为准。

## 坑位 11：同步树/详情页没有直接的教材字段可查

- **现象**：想从详情页确认教材版本，发现桌面版与移动版详情页都无"教材版本"字段；列表页也没有教材筛选行。
- **修复**：用三层核验替代（学年+内容+同步树 ID 比对），见 references/textbook-verification.md。

## 坑位 12：CDP 代理频繁断连

- **现象**：`{"error":"本次连接的浏览器是 chrome，但现在没连上..."}`（Chrome 重启/休眠后高发）；截图接口偶发 Connection refused（重试即可）。
- **修复**：`pkill -f cdp-proxy.mjs; sleep 2; open -a "Google Chrome"; sleep 4`，再跑 check-deps.mjs 确认 `proxy: ready`。批量任务中途断连需重启任务（脚本可断点续传，影响不大）。

---

## 误诊教训汇总（方法论层面）

1. **空失败先查可见性，不要先怀疑资源/账号/限速**——一击定位省 3 轮排查。
2. **验收标准先对齐再动手**："沪教版（五四制）"的大范围定义 ≠ 用户新教材 edition 的严格定义，术语错位导致全量返工。
3. **结论措辞不超出验证范围**：只验证了标题和地区就别说"教材版本全部核验通过"。
4. **报错分层定位**：eval 报 Uncaught 时用二分法隔离（先 document.title，再 querySelectorAll，再 map/filter 组合），常见根因是 null 解引用与非法选择器，而非页面本身。
